## 📋 Task Report: 저장된 랩 활용과 개인 표본 전략 분석

### 1. Pre-Review (Plan)

- **Orchestrator Feedback**: 과거 업로드의 계측 부재와 정밀 분석의 표본 부족을 구분한다. 저장된 유효 랩은 관측 통계로 제공하고, 한 사람의 독립된 여러 경기에는 명시적으로 참고용 계산을 허용한다. 재현한 랩 경계의 추월 패킷 귀속 오류도 수정한다.
- **독립 리뷰어 Feedback (fresh-context)**: 늦은 패킷이 최신 freshness를 덮어쓰지 않도록 하고, 기본 분석의 수량 실패에만 원본 자료로 재시도할 것을 권고했다. 연료의 정확한 랩·시간·타이어 일치와 명시적 빈 제외 사유, 제한된 집계 범위, 동적 최소 기준 문구를 확인했다. 후속 독립 리뷰가 발견한 공유 Flags 배열 변경 문제도 반영했다.
- **Refinement**: 수집 시각을 랩 경계에 맞추고 큐·저장 창을 제한했다. 늦은 플래그 추가 전에 배열을 복제한다. 구버전 웹에는 기본 기준을 유지하도록 `allowLimitedEvidence`를 선택적으로 협상한다.
- **Task Breakdown**: 수집 패킷 귀속(상), 과거 관측 집계/API(중), 참고용 모델 경로(상), 기존 디자인의 화면/호환 처리(중), 회귀·빌드·배포 검증(중).

### 2. Implementation Details

- **Assumptions**: **[Assumption]** 참고용 최소 기준은 1명·서로 다른 3경기·정상 랩 12개다. 기존 경기당 4랩 검증을 유지하는 초기 제품 정책이며, 예측 정확도 검증값이 아니다. [결정 근거](../../history/20260913-strategy-reference-evidence.md)를 기록했다.
- **Key Changes**: 최근 적격 레이스 업로드 최대 300개의 타이어별 유효 랩 수·중앙값·범위와 실제 측정된 연료 중앙값·별도 표본 수를 표시한다. 정밀 계측이 없거나 분석 조건 카드가 없어도 과거 타이밍이 표시된다. 없는 연료는 `측정 없음`이다.
- 기존 기본 분석은 그대로 먼저 실행한다. 표본 수가 부족할 때만 같은 회귀식과 물리 검증으로 참고용 계산을 시도한다. 1명 표본도 결과에 실제 수량·`참고용 · 표본 제한`·다른 경기 정확도 미검증을 표시한다. ERS 기준은 유지한다.
- 수집기에서 DRS·2026 오버테이크 활성 패킷을 시각 기준으로 해당 랩에 배정한다. 도착 순서, 뒤늦은 이전 랩 패킷, 짧은 활성 구간, 되감기 이후 이전 패킷, 큐 초과를 검사한다.
- 서버 권한 검사와 수동 전략 계산·새로고침·응답 취소를 유지한다. 화면은 기존 카드·표·글꼴·색상을 재사용하며 CSS 변경은 없다.

### 3. Final Convention Review

- **Layer Analysis**: Presentation은 집계 사실과 분석 수준을 구분해서 표시한다. Service는 기존 추정기에 최소 표본만 인자로 전달하고 검증 규칙을 공유한다. Repository는 최근 업로드를 먼저 제한한 뒤 유효 랩을 집계하고 연료를 정확히 대조한다. 마이그레이션은 없다.
- **Simplicity Check**: 기존 추정기와 UI 스타일을 재사용했다. 공개 WebRTC DTO와 전송 페이로드에 추가 필드가 없으므로 24대 차량 데이터의 크기는 증가하지 않는다. 미측정값을 추정하거나 기존 업로드를 재작성하지 않는다.
