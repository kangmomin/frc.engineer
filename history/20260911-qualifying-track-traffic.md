# 퀄리파잉 기록을 왼쪽에 모으고 트랙 앞뒤차를 별도 패널로 표시

- **날짜**: 2026-09-11
- **이슈**: 사용자 요청 — 퀄리파잉에서 드라이버와 기록 사이가 넓어 온보드와 함께 보기 어렵고, 순위·기록과 무관한 실제 트랙 앞뒤차를 쉽게 확인해야 한다. 기존 앞뒤차는 My Lap 하단의 작은 코드로 표시되며 개러지 차량을 포함하거나 첫 결승선 통과 전 차량을 제외할 수 있었다.
- **결정**:
  - 레이스 표처럼 데이터 열 너비를 고정하고 여유 공간을 마지막에 둔다. 좁은 화면에서는 헤더와 모든 데이터 열을 함께 가로 스크롤한다.
  - 사이드바 상단의 Track Traffic에 본인 차량 기준 앞뒤차 이름·주행 상태·거리(m)를 표시한다. 기존 피트/개러지의 순위 위협 정보는 Threat Watch라는 별도 제목과 초 단위로 구분한다.
  - 각 차량의 `lapDistance`를 트랙 길이 안으로 정규화한 뒤 순서를 구한다. 분류 순위·베스트 기록·완료 랩 수는 이 계산에 사용하지 않는다.
  - 주행 상태 1~4인 차량 중 피트·명시적 비활성(결과 상태 1)·경기 종료 제외 상태(4~7)를 거른다. 개러지 상태 0은 생략된 경우도 포함해 제외한다. 결과 상태 3의 인랩은 유지한다.
  - 이전 Sender 호환을 위해 결과 상태 0/생략은 명시적인 주행 상태가 있는 경우 허용한다. 이는 결과 상태 1까지 허용하는 레이스 Pit Exit 정책과 별개의 퀄리파잉 기준이다.
  - 기준 차량/트랙 위치 정보가 없는 경우와 본인 차량만 트랙에 있는 경우를 구분한다.
- **결정자**: 사용자(기능 요구) / 에이전트(구현 세부 및 독립 리뷰 반영)
- **근거**:
  - `docs/F1 25 Telemetry Output Structures.txt`의 LapData 명세는 첫 결승선 통과 전 음수 거리를 허용한다. 원시 음수를 먼저 정렬하면 정상 거리 차량과 앞뒤 관계가 뒤바뀌므로 정규화를 선행한다.
  - [RTC 상태값 보존 후속 검증](20260721-pitexit-racing-rival-status-blacklist.md)의 2026-09-05 기록은 이전 송신 경로가 결과 상태를 0으로 제거했음을 확인한다. 이 호환 예외는 명시적인 비활성 상태 1의 유효성을 의미하지 않는다.
  - 기존 `useTrackGaps`와 My Lap 파생 모델을 재사용하면 화면 표시와 계산을 분리하면서 송신 변경 없이 요구를 충족한다. 24대·TrackMap 포함 조건에도 추가 전송 필드와 바이트는 0이며 256 KiB 수신 한도 및 128 KiB 버퍼에 추가 부담을 주지 않는다.
- **기각된 대안**: 순위 인접 차량이나 베스트 랩 차이로 주행 중 앞뒤차를 대체하는 방식은 사용자 요구와 다르다. 거리에서 임의로 초 단위 간격을 추정하는 기능은 추가하지 않는다.
- **수정 내역**: `ClassificationPanel`, `TrackTrafficPanel`, `MyLapPanel`, `QualifyingView`, `derive/myLap`, `useTrackGaps` 및 사용 가이드·관련 검증.
- **검증**: 관련 단위 테스트 131개, 실제 Chrome의 1280/1920/2560 폭·24대 양방향 스크롤·트랙 앞뒤차/추월/기준 차량/개러지 전환·기존 퀄리파잉/리플레이 회귀 검증 통과. 웹 프로덕션 빌드, 수정 파일 ESLint 및 독립 최종 리뷰 통과.
- **재발 시 대응**: 음수 거리 제외, 순위 기반 앞뒤차, 결과 상태 1 허용 또는 피트 위협 정보의 물리적 거리 오독이 재제기되면 이 문서와 회귀 테스트를 기준으로 판단한다.
