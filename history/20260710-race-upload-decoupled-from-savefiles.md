# 레이스 요약 업로드·디브리프를 saveFiles에서 분리 (서버 전송은 무조건 수행)

- **날짜**: 2026-07-10
- **이슈**: 레이스 종료 콜백이 `!saveFiles → 조기 return`이라 파일 저장을 끄면 요약 생성·
  PostRaceDebrief 브로드캐스트·플랫폼 자동 업로드까지 전부 스킵됐다 (기능 감사에서 발견).
  "파일은 안 남기고 서버에만 올리기" 시나리오가 불가능했다.
- **결정**: **데이터는 무조건 서버로 넘어가도록** 요약 생성·디브리프·업로드를 `saveFiles`와
  완전 분리. `saveFiles`는 로컬 저장(요약 파일·리플레이·패킷 로깅) 여부만 결정한다.
- **결정자**: 사용자
- **근거**: 서버 수집(플랫폼)은 제품의 핵심 데이터 경로 — 로컬 디스크 정책이 이를 게이팅하면 안 됨.
- **[Assumption]**: "무조건"은 saveFiles 의존 제거로 해석. **페어링 토큰 + autoUpload 토글
  게이팅은 유지** — 토큰 없이는 업로드가 물리적으로 불가(401)하고, autoUpload는 사용자의
  명시적 업로드 동의 스위치이므로. 이 토글까지 무시해야 하면 후속 결정 필요.
- **기각된 대안**: 없음
- **수정 내역** (`cmd/sender/main.go`, 커밋 `0e2764a5`):
  - `SetRaceSummaryRecording(true)` 상시 활성 (시작 시 + 설정 변경 시 재토글 제거)
  - 종료 콜백: 조기 return 제거 → 요약 생성·`latestRaceSummary` 갱신·브로드캐스트·업로드는
    항상, `rs.Save`(요약 파일)와 리플레이 타임라인 부착만 `saveFiles` 분기
  - `SetReplayRecording`·패킷 로깅은 종전대로 `saveFiles` 지배
- **알려진 한계**: saveFiles off에서 자동 업로드가 실패하면 디스크에 파일이 없어 수동 재업로드
  (`POST /api/races/{id}/upload`, 디스크 로드 기반)로 복구 불가. 재시도 큐 도입 시 함께 해소.
- **재발 시 대응**: 업로드/디브리프에 saveFiles 게이팅을 되돌리자는 제안이 나오면 본 문서 인용 종결.
