# UDP 종료는 최종 상태로 두고 전달 연결은 DNS 재조회 후 재사용한다

- **날짜**: 2026-09-12
- **이슈**: 기능·성능 개선의 독립 리뷰에서 Listener 종료·포트 변경 경합, DNS 조회 동안 Forward 정지, 설정 갱신 시 동일 socket 재생성이 확인됐다. Sender와 Server는 HTTP 요청 드레인 전에 Forwarder를 종료하므로 대기 중 설정 요청이 연결을 재생성할 수 있었다.
- **결정**: [Assumption] `Listener.Close`와 `Forwarder.Close`는 해당 객체의 영구 종료로 해석한다. Listener는 종료 후 Rebind에 `net.ErrClosed`를 반환하고, Forwarder는 종료 후 설정 갱신을 무시한다. 진행 중 DNS 조회는 Forward나 Close를 막지 않으며, 조회 후 준비한 연결은 종료 상태를 재확인해 폐기한다.
- **결정자**: 에이전트. 사용자 요청에 따른 로컬 수정이며 독립 리뷰 권고를 반영했다.
- **근거**: 호출부는 종료한 객체를 다시 사용하지 않는다. 수신 goroutine이 시작된 뒤에는 그 goroutine만 packet 채널을 닫아 전송·종료 경합을 없앤다. Forwarder의 종료 상태를 설정 게시 직전에도 확인해 늦게 끝난 갱신의 연결 재생성을 막는다.
- **기각된 대안**: Forward와 같은 잠금으로 DNS를 수행하는 방식은 수신 지연을 일으킨다. Update 전용 잠금을 Close까지 기다리게 하면 DNS 지연이 종료를 막는다. 호스트명 문자열만으로 재사용하면 DNS 주소 변경을 놓친다.
- **재사용 규칙**: 활성 대상은 매 갱신마다 DNS를 다시 조회한다. 같은 대상 문자열과 같은 해석 결과일 때 기존 연결을 재사용하며, 중복 설정 항목은 기존 인덱스와 일대일로 대응한다. 해석 실패 항목은 연결 없이 남기고 정상 항목은 적용하는 기존 동작을 유지한다.
- **수정 내역**: `internal/udp/listener.go`, `internal/udp/forwarder.go` 및 실제 UDP·DNS 회귀 테스트. 커밋은 생성하지 않았다.
- **검증**: [작업 보고서](../docs/reviews/20260912-udp-improvements.md). 종료 상태 검사를 제거하는 변이에서도 새 연결의 재활성화를 테스트가 검출한다.
- **재발 시 대응**: 동일한 수명주기·DNS 재사용 정책 논의는 이 문서를 참조한다.
