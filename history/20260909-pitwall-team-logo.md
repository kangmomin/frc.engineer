# Pit Wall 팀 로고는 인라인 SVG 마크 + 실제 로고 드롭인 병행으로 간다

- **날짜**: 2026-09-09
- **이슈**: "pitwall 에서 드라이버별 팀 로고가 닉네임 왼쪽에 뜨게 해줘" 요청. 그런데 레포에는
  이미지/SVG 에셋이 **하나도 없고**(`web/public`은 `_redirects` 뿐), 실제 F1 팀 로고는 상표물이라
  에이전트가 받아와 커밋할 수 없다. 선택지: ①인라인 SVG 마크 자체 제작 ②사용자가 로고 파일 제공
  ③기존 `TEAM_SHORT` 텍스트 배지를 이름 왼쪽으로 이동.
- **결정**: ①+②를 **병행**한다. 기본은 팀별 인라인 SVG 마크(`web/src/ui/TeamLogo.tsx`)로 즉시 동작하고,
  `web/src/assets/team-logos/<teamId>.svg|png`에 실제 로고 파일을 넣으면 그 팀만 자동으로 진짜 로고로
  대체된다(코드 수정 불필요). 수집은 빌드타임 `import.meta.glob`.
- **결정자**: 합의 (사용자가 "실제 로고 처럼 쓸 수 있어?"로 실물 충실도를 요구 → 드롭인 경로 추가)
- **근거**:
  - 단순한 마크(메르세데스 삼각별, 맥라렌 스피드마크, 알핀 A)는 손으로 그려도 실물에 근접하지만,
    디테일이 많은 로고(페라리 도약마, 레드불 황소, 애스턴 윙, 캐딜락 크레스트)는 16px에서 충실
    재현이 불가능하다. 두 경로를 함께 두면 "지금 당장 동작"과 "원하면 실물"을 모두 만족한다.
  - 런타임 `<img onError>` 폴백을 쓰지 않은 이유: 존재 여부가 번들 시점에 확정되어 폴백 깜빡임과
    헛요청이 없다. 더해 `web/public/_redirects`의 `/*  /index.html  200` 캐치올 때문에 없는 경로도
    200을 반환해 상태코드 기반 존재 확인 자체가 불가능하다.
- **기각된 대안**:
  - ③ 텍스트 배지 이동: 가장 싸지만 "로고"가 아니다.
  - `getTeamName`의 미매핑 폴백을 `'Unknown'` → `` `Team #${id}` ``로 함께 변경: **회귀 유발**.
    `web/src/hub/screens/Strategy.tsx:36,47,117`이 `getTeamName(teamId ?? -1)`로 호출해 팀 정보 없는
    전략 기록이 `'Team #-1'`로 표시된다. `analysisPlayback.ts:110-114`는 이미 자체 처리하므로 이득도 없다.
    → `getTeamShort`만 변경.
- **수정 내역**: `web/src/ui/TeamLogo.{tsx,derive.ts,module.css,test.ts}` 신규,
  `web/src/ui/index.ts`, `web/src/constants/teamColors.ts`(`getTeamKey` 추가),
  `web/src/views/pitwall/{LeaderboardPanel.tsx,columns.ts,derive/leaderboardRows.ts}`.
  기존 `TEAM_SHORT` 텍스트 배지는 **사용자 결정으로 유지**(로고는 왼쪽에 추가만).
- **재발 시 대응**: "배지와 로고가 중복이니 하나로 합치자" 또는 "실제 로고 파일을 직접 받아오자"가
  재제기되면 본 문서를 인용하여 종결한다.

## 후속 결정: 16px에서 뭉개지는 마크는 실물 충실도를 버린다 (2026-09-09)

- **이슈**: 목업 데이터의 teamId가 0~9라 화면 검증이 10종만 커버했다. F1 26 사용자가 실제로 보게 될
  `audi`(10/485)·`cadillac`(486)을 16px로 따로 렌더해 확인하니, **아우디 4링이 링 하나당 4.5px로
  줄어 구멍이 메워지고 붉은 알약 한 덩어리**로 보였다(캐딜락 크레스트는 정상 판독).
  앞서 같은 이유로 애스턴(하이픈처럼 보임)·RB(레터마크 뭉갬)·레드불(구불한 점)도 재작업했다.
- **결정**: 아우디는 링을 **2개**로 줄인다(`r=5.1`, `cx 7.6/16.4`). 실물은 4링이지만 16px에서
  판독되지 않으면 로고로서 의미가 없다.
- **결정자**: 에이전트 (실측 스크린샷 4×확대 비교: 4링 sw2 / 4링 sw1.4 / 2링 / 3링 / 4링 r4 — 2링만 판독됨)
- **근거**: 팀 식별은 옆의 `[AUD]` 텍스트 배지가 이미 담당한다(사용자가 유지 결정). 로고는 한눈에
  구분되는 실루엣이면 충분하고, 판독 불가능한 충실도는 아무것도 전달하지 못한다. RB 마크에 이미
  같은 판단을 적용했다. 실물이 필요하면 드롭인 경로(`assets/team-logos/485.svg`)가 있다.
- **기각된 대안**: 4링을 크게(`r=4`, `cx 5.2~20.8`) → 여전히 흐릿하고 `cx 20.8+r4=24.8`로
  viewBox(24) 밖으로 잘린다. 3링 → 4링과 마찬가지로 뭉갠다.
- **수정 내역**: `web/src/ui/TeamLogo.tsx`의 `MARKS.audi`.
- **재발 시 대응**: "아우디는 4링이 맞다"가 재제기되면 본 섹션을 인용하여 종결한다.

## 후속 결정: 마크를 16px 광학 기준으로 정규화한다 (2026-09-10)

- **날짜**: 2026-09-10
- **이슈**: 사용자가 "디자인적으로 이상한 부분"을 확인 요청. 실제 렌더를 픽셀 측정한 결과 두 가지가
  나왔다. ①**마크 높이가 7px~14px로 2배 편차** — 메르세데스·페라리·캐딜락은 16px 박스를 꽉 채우는데
  맥라렌·애스턴(7px)·아우디(8px)는 절반 높이라 아이콘 열이 들쭉날쭉하고 흐린 얼룩처럼 보였다.
  ②**레드불 마크가 P1에서 노이즈로 읽힘** — 원(태양)+삼각 2개가 16px에서 서로 떨어진 점 무더기가 된다.
  하필 항상 맨 위에 오는 팀이라 제일 먼저 눈에 들어오는 마크가 제일 안 읽혔다.
- **결정**:
  - `stroke-width` **2 → 2.5**. 16px 환산 1.33px는 1x DPR 안티에일리어싱에 먹혀 흐려지는 게 흐림의 주원인.
  - 낮은 마크를 키운다: 애스턴 7→11px, 맥라렌 7→11px, 아우디 8→10px.
  - 높은 마크를 살짝 줄인다: 페라리·캐딜락 방패 0.88배, 메르세데스 링 `r` 9→8.2(삼각별 팔도 같은 비율).
  - 레드불은 **맞물린 단일 실루엣**(`M2 4.5L12 12 22 4.5v15L12 12 2 19.5z`)으로 교체한다.
- **결정자**: 사용자 ("3건 전부 수용")
- **근거**:
  - 결과 실측: 높이 밴드 **7~14px(2.00배) → 10~14px(1.40배)**. 세로 중심 편차는 ±0.5px로 유지.
  - 레드불은 앞서 두 번 손봤는데도 안 읽혔다. 세 번째 미세조정 대신 실루엣을 하나로 합치는 쪽이
    맞다 — 조각이 3개라 뭉개진 게 아니라 **떨어져 있어서** 뭉개졌기 때문이다.
  - 팀 식별은 옆 `[RBR]` 텍스트 배지가 이미 담당한다(사용자 유지 결정). 판독되는 실루엣이
    실물 충실도보다 우선한다 — RB 레터마크·아우디 4링에 이미 적용한 같은 판단이다.
- **제약**: 아우디 `r`은 **5.9가 상한**이다. 링 2개가 가로로 놓여 세로가 아니라 **가로가 viewBox 24를
  먼저 채운다**. 그래서 아우디만 밴드 하단(10px)에 남는다.
- **함께 갱신**: 위 "16px에서 뭉개지는 마크" 절의 아우디 수치(`r=5.1`, `cx 7.6/16.4`)는 본 결정으로
  `r=5.9`, `cx 7.4/16.6`으로 대체되었다. 링 2개라는 결정 자체는 그대로다.
- **수정 내역**: `web/src/ui/TeamLogo.tsx`(마크 7종), `web/src/ui/TeamLogo.module.css`(`stroke-width`).
- **재발 시 대응**: "레드불은 황소여야 한다" 또는 "마크 크기를 실물 비율대로 두자"가 재제기되면
  본 섹션을 인용하여 종결한다.
