# 전략 수집에서 정상 마모와 출발 전 시계 초기화를 구분

- **날짜**: 2026-09-11
- **이슈**: 전략 근거가 업로드되어도 타이어 정상 마모를 손상으로 분류하고 출발 전 시계 초기화를 플래시백으로 분류하여 조건 탐색에서 제외했다. 화면도 저장된 기록과 비교 가능한 조건을 구분하지 않았다.
- **결정**: 타이어 마모에 포함된 정수 손상 표현을 허용하고, 완료 랩이 없는 출발 전의 영점 타이머 초기화에만 추정 플래시백 예외를 적용한다. 실제 손상·되감기·누락된 계측의 제외는 유지한다. 화면은 기존 API의 조회 범위 기록 수를 조건 수와 별도로 표시한다.
- **결정자**: 사용자(수정·배포 범위 승인), 에이전트(세부 구현과 독립 리뷰 반영)
- **근거**: 실제 캡처 8,960개 표본에서 타이어 손상 정수는 측정 마모의 정수 부분과 같았다. 다른 실제 캡처의 세 번의 시계 초기화는 프레임이 정상 증가하고 직전/현재 모두 1랩, 현재/직전 랩 타이머가 0이며 `FLBK` 이벤트가 없었다.
- **Assumptions**: `[Assumption]` 정수 손상 값과 소수 마모 값 사이의 정수화 범위는 `ceil(wear)`까지 허용한다. 그 범위를 넘는 손상, 100% 손상, 유한하지 않거나 범위를 벗어난 마모 값은 제외한다.
- **기각된 대안**: 저장된 `damage`·`flashback` 플래그를 일괄 삭제하면 실제 손상·되감기도 허용된다. 기존 근거에는 판정을 다시 수행할 전체 원본이 없으므로 소급 해제하지 않는다. 2025 UDP 형식으로 보낸 2026 차량의 누락된 Manual Override 상태도 꺼짐으로 추정하지 않는다.
- **수정 내역**: `internal/telemetry/strategy_evidence.go`와 회귀 테스트, `web/src/hub/screens/Strategy.tsx`와 실제 브라우저 회귀, API·계산 문서. Driver Pack v4.59.0에서 신규 수집부터 적용한다.
- **재발 시 대응**: 이 문서를 기준으로 타이어의 정상 마모와 추가 손상, 출발 전 시계 초기화와 실제 되감기를 구분한다. 원본 근거 없이 기존 제외 판정을 소급 해제하지 않는다.

## 📋 Task Report: 전략 집계 판정 수정

### 1. Pre-Review (Plan)
- **Orchestrator Feedback**: 수집기 판정 수정(중간), 화면 안내(낮음), 회귀·실제 캡처 검증(중간), 릴리스(중간)로 분해했다.
- **독립 리뷰어 Feedback**: 스킬 밖 구현은 fresh-context 서브에이전트 한 명으로 독립 검토했다. 정상 마모의 정수화와 100% 손상 경계, 실제 되감기 보존, 수집 0건과 정상 랩 0건 구분을 검토했다.
- **Refinement**: 초기화 예외는 직전/현재 랩 번호·현재 타이머·직전 타이머까지 확인한다. 화면은 최소 계산 표본 기준을 조건 카드 표시 기준으로 설명하지 않는다.

### 2. Implementation Details
- **Assumptions**: 위 정수화 범위의 명시된 가정 외 추가 기능 가정은 없다.
- **Key Changes**: 정상 마모와 출발 전 초기화 오판을 수정했다. 미수집·집계 제외 상태와 조회 범위 수집 수를 표시하고, 2026 차량의 UDP 형식 안내를 제공한다.

### 3. Final Convention Review
- **Layer Analysis**: 수집기는 원본 판정, Presentation은 기존 응답의 표시를 담당한다. 계산 Service와 Repository 계약 및 WebRTC DTO는 변경하지 않는다.
- **Simplicity Check**: 새 의존성·API·테이블 없이 기존 판정 함수와 화면 분기만 수정했다. 독립 최종 리뷰에서 릴리스 차단 사항이 없었다.

### 4. Status
- **Verification**: 실제 값으로 재현한 실패를 확인한 뒤 회귀가 통과했다. 실제 UDP 캡처 2종의 340,787개 관련 패킷을 오류 없이 해석했고 정상 랩 3개/2개 및 조건 1개씩을 생성했다. 실제 브라우저의 수집/조건 수·검색·미수집/제외 상태·재조회·권한·지연 응답과 웹 빌드, 수집/모델/레이스 race detector, 새 PostgreSQL의 업로드→권한→조회→계산 HTTP 통합 검증을 통과했다.
- **Cleanup**: 실제 캡처 재생용 임시 테스트는 삭제하고 작은 고정 회귀만 유지한다. 임시 PostgreSQL과 릴리스 검증 세션은 검증 완료 후 정리한다.
