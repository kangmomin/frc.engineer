# Decision History

수정 내역(무엇을 고쳤는지)이 아니라 **결정 내역(왜 그렇게 하기로 했는지)** 을 기록하는 로그다.
코드 리뷰 finding 채택/기각, 설계 트레이드오프, 하위호환 정책, 컨벤션 채택처럼 **판단이 개입된
항목만** 남긴다. 단순 버그 수정·오타·기계적 리팩토링은 기록하지 않는다.

## 목적

- 같은 이슈가 이후 단계(리뷰, simplify, 후속 작업)에서 재논의되는 것을 차단한다.
  동일 이슈가 재제기되면 해당 로그를 인용하고 즉시 종결한다.
- "왜 이렇게 되어 있지?"에 대한 답을 커밋 메시지보다 높은 해상도로 보존한다.

## 파일 규칙

- 위치: `history/` (이 폴더)
- 파일명: `YYYYMMDD-<kebab-case-주제>.md` — 예: `20260710-fuel-team-gating-sentinel.md`
- 결정 1건당 1파일. 같은 이슈의 후속 결정은 새 파일 대신 기존 파일에 섹션을 추가한다.

## 템플릿

```markdown
# <한 줄 결정 요약>

- **날짜**: YYYY-MM-DD
- **이슈**: 무엇이 문제였나, 어떤 선택지가 있었나 (출처: 리뷰 finding, file:line, 대화 등)
- **결정**: 무엇을 하기로 (또는 하지 않기로) 했나
- **결정자**: 사용자 / 에이전트 / 합의
- **근거**: 왜 그렇게 결정했나 (트레이드오프 1~3줄)
- **기각된 대안**: 무엇을 왜 기각했나 (없으면 "없음")
- **수정 내역**: 결정에 따라 진행한 실제 수정 (커밋 해시, 주요 파일) — 수정 없이 유지 결정이면 "없음(유지)"
- **재발 시 대응**: 동일 이슈 재제기 시 본 문서 인용으로 종결
```
