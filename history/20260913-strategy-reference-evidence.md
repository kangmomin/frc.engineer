# 개인 레이스 기록으로 관측 통계와 표본이 제한된 전략을 제공한다

- **날짜**: 2026-09-13
- **이슈**: 많은 랩을 저장해도 전략 계측이 없는 과거 업로드는 화면에 활용되지 않았고, 정상 랩이 충분한 한 사람의 기록도 3명 기준 때문에 전략을 계산할 수 없었다. 사용자가 원인 분석 후 수정을 요청했다.
- **결정**: 과거 레이스의 유효 랩타임·타이어를 관측 통계로 보여준다. 정밀 계측이 있는 기록은 기존 분석을 먼저 시도하고, 표본 수만 부족하면 같은 추정기를 참고용 최소 기준으로 다시 실행한다. 결과에는 `sampleLevel`, 실제 사용 표본 수와 적용 기준을 표시한다.
- **결정자**: 사용자(문제 수정·기존 화면 디자인 유지), 에이전트(구체적 집계 및 참고용 기준)
- **근거**: 일반 랩타임만으로 연료·타이어 나이·트래픽을 복원할 수 없다. 관측된 사실을 먼저 제공하고, 필요한 측정값과 식별 가능한 모델이 있는 개인 기록은 한 사람이라는 이유만으로 배제하지 않는다.
- **기각된 대안**: 모든 오염·물리 검증을 완화하거나 과거 연료 값을 추정해서 채우는 방식은 사용하지 않는다. 랩타임 관측 통계를 타이어 성능 순위로 제시하지 않는다.
- **수정 내역**: `internal/platformsvc/strategy_observations.go`, `internal/strategy/model.go`, `cmd/platform/strategy.go`, `web/src/hub/screens/Strategy.tsx`, `docs/api/strategy-lab.md` 및 관련 회귀 검사.
- **재발 시 대응**: 같은 표본 정책 또는 관측/분석 구분이 재제기되면 본 문서를 인용한다. 실제 다른 경기에서의 검증 자료가 생기면 정확도 정책을 별도로 재평가한다.

## 참고용 기준과 유지되는 검증

- **[Assumption]** 참고용 시작 기준을 1명·서로 다른 3경기·정상 랩 12개로 정했다. 기존 경기당 4랩 기준을 유지한 초기 제품 정책이며, 예측 정확도를 검증한 임계값이 아니다.
- 각 컴파운드도 3경기와 3랩 이상의 타이어 사용 나이 범위를 요구한다. 한 경기의 중복 업로드로 독립 경기 수를 채울 수 없다.
- 기존 기본 표본 기준은 3명·6경기·40랩이다. `minimum-evidence` 실패에만 원본 자료로 재시도하며, 회귀식 식별 불가·불안정 계수·불가능한 타이어 재고는 그대로 거절한다.
- 필수 계측, 경기 중 고정 셋업, 트래픽·손상 등 제외 기준, 피트 관측 3경기와 사용 나이 범위는 유지한다. ERS 분석의 3명·6경기 기준도 유지한다.
- 이퀄 성능 조건에서는 조건 키에서 제거하는 TeamID의 누락을 허용한다. 논이퀄에서는 차량 차이를 구분해야 하므로 계속 요구한다.

## 과거 업로드와 서버/웹 호환

- 관측 통계는 같은 트랙·게임의 최근 적격 레이스 업로드 최대 300개를 먼저 선택한 뒤 서버가 유효하다고 판정한 랩을 집계한다. 최대 확장량은 300 × 500랩이다. 업로드 건수는 중복 제거된 독립 경기 수가 아니다.
- 연료 통계는 같은 랩 번호·시간·타이어의 정밀 계측과 정확히 일치하고, 제외 사유 없이 시작/종료 연료가 모두 측정된 랩에만 제공한다. 측정 랩 수를 별도로 표시하며 없는 값은 `null`이다.
- 새 웹은 서버가 `referenceMinimums`를 반환할 때만 POST에 `allowLimitedEvidence: true`를 보낸다. 생략된 요청은 기존 기본 기준으로 처리하므로, 이전 웹이 참고용 결과를 설명 없이 표시하지 않는다.
- GET의 추가 필드는 웹에서 생략 또는 `null`을 허용한다. 기존 화면의 카드·표·글꼴을 그대로 사용한다.
- 이 변경은 인증된 HTTP 집계 응답과 로컬 전략 수집기 대상이다. 공개 WebRTC DTO, 24대 차량 데이터 및 128KB 전송 버퍼의 최대 크기는 증가하지 않는다.
